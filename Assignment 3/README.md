# Assignment 3: Архитектура GPU и оптимизация CUDA-программ
## Контрольные вопросы

### 1. Какие основные типы памяти существуют в архитектуре CUDA и чем они отличаются по скорости доступа?

В архитектуре CUDA используются следующие основные типы памяти:
- **Регистры** — самая быстрая память, доступная отдельному потоку.
- **Разделяемая (shared) память** — быстрая память, общая для потоков одного блока.
- **Глобальная память** — основная память GPU, доступная всем потокам, но с высокой задержкой.
- **Константная и текстурная память** — специализированные типы памяти, оптимизированные для определенных шаблонов доступа.

Скорость доступа уменьшается в следующем порядке:  
регистры → shared memory → глобальная память.

### 2. В каких случаях использование разделяемой памяти позволяет ускорить выполнение CUDA-программы?

Разделяемая память позволяет ускорить выполнение программы, когда:
- данные многократно используются потоками одного блока;
- требуется уменьшить количество обращений к глобальной памяти;
- необходим быстрый обмен данными между потоками блока.

Наибольший эффект достигается при правильной организации доступа и синхронизации потоков.

### 3. Как шаблон доступа к глобальной памяти влияет на производительность GPU-программы?

Производительность сильно зависит от того, является ли доступ **коалесцированным**:
- при коалесцированном доступе потоки варпа обращаются к соседним адресам памяти, что минимизирует количество транзакций;
- при некоалесцированном доступе требуется больше обращений к памяти, что значительно увеличивает время выполнения.

### 4. Почему одинаковый алгоритм на GPU может показывать разное время выполнения при разных способах обращения к памяти?

Хотя вычислительная логика алгоритма остается неизменной, различные способы обращения к памяти приводят к:
- разному количеству обращений к глобальной памяти;
- различной степени коалесцированности;
- различным задержкам доступа.

В результате время выполнения может отличаться в несколько раз.

### 5. Как размер блока потоков влияет на производительность CUDA-ядра?

Размер блока потоков влияет на:
- степень заполнения вычислительных ресурсов GPU (occupancy);
- количество одновременно выполняемых варпов;
- эффективность использования shared memory и регистров.

Слишком маленькие блоки приводят к недоиспользованию GPU, а слишком большие - к дефициту ресурсов. На практике часто оптимальными являются размеры 128–256 потоков на блок.

### 6. Что такое варп и почему важно учитывать его при разработке CUDA-программ?

**Варп** — это группа из 32 потоков, выполняющихся синхронно на GPU.  
Важно учитывать варпы, потому что:
- расхождение ветвлений внутри варпа приводит к снижению производительности;
- оптимальный размер блока обычно кратен размеру варпа;
- коалесцированный доступ определяется на уровне варпа.

### 7. Какие факторы необходимо учитывать при выборе конфигурации сетки и блоков потоков?

При выборе конфигурации необходимо учитывать:
- размер обрабатываемых данных;
- архитектуру GPU;
- ограничения по shared memory и регистрам;
- требования к коалесцированному доступу;
- баланс между числом блоков и потоков для максимальной загрузки GPU.

### 8. Почему оптимизация CUDA-программы часто начинается с анализа работы с памятью, а не с изменения алгоритма?

В большинстве CUDA-программ узким местом является не вычисление, а доступ к памяти.  
Оптимизация работы с памятью (коалесцированный доступ, использование shared memory, уменьшение обращений к глобальной памяти) часто дает значительно больший прирост производительности, чем изменение самого алгоритма.
