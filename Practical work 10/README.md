# Отчет по практической работе  
## Анализ производительности параллельных и гибридных приложений (CPU, GPU, MPI)

---

## Цель работы

Целью данной работы является исследование производительности параллельных программ на CPU, GPU и в распределенной среде, а также анализ факторов, влияющих на масштабируемость и эффективность вычислений. В рамках работы рассматриваются OpenMP, CUDA, гибридные вычисления CPU + GPU и распределенные вычисления на основе MPI.

---

## Задание 1. Анализ производительности CPU-параллельной программы (OpenMP)

### Описание реализации

Для анализа производительности CPU была разработана программа на языке C++ с использованием технологии OpenMP. Программа выполняет обработку большого массива данных, вычисляя сумму элементов, среднее значение и дисперсию. Основные вычисления реализованы в виде параллельных циклов с использованием директив `#pragma omp parallel for`.

Для измерения времени выполнения использовалась функция `omp_get_wtime()`.

---

### Профилирование и анализ

Параллельными частями программы являются циклы вычисления суммы и дисперсии массива. Последовательная часть включает инициализацию данных, вычисление среднего значения и операции ввода-вывода.

При увеличении числа потоков наблюдается ускорение выполнения программы, однако рост ускорения замедляется при большом числе потоков. Это связано с наличием последовательной части программы и накладными расходами на синхронизацию потоков.

---

### Закон Амдала

Согласно закону Амдала, максимальное ускорение параллельной программы ограничено долей последовательного кода:

\[
S = \frac{1}{(1 - P) + \frac{P}{N}}
\]

где \(P\) — доля параллельной части, \(N\) — число потоков. Полученные результаты подтверждают данный закон: даже при увеличении числа потоков ускорение имеет верхний предел.

---

## Задание 2. Оптимизация доступа к памяти на GPU (CUDA)

### Описание реализации

Были реализованы две версии CUDA-ядра для обработки массива данных:

1. Ядро с коалесцированным доступом к глобальной памяти, при котором соседние потоки обращаются к соседним элементам памяти.
2. Ядро с некоалесцированным доступом, при котором адреса памяти выбираются с большим шагом, что приводит к неэффективным обращениям.

Для измерения времени выполнения использовались CUDA-события (`cudaEvent`).

---

### Оптимизация

Для повышения производительности были применены следующие методы:
- использование коалесцированного доступа к глобальной памяти;
- оптимизация организации потоков;
- использование разделяемой памяти для уменьшения количества обращений к глобальной памяти.

---

### Анализ результатов

Результаты показали, что коалесцированный доступ к памяти значительно ускоряет выполнение CUDA-ядра. Некоалесцированный доступ приводит к увеличению количества транзакций памяти и существенному падению производительности GPU.

---

## Задание 3. Профилирование гибридного приложения CPU + GPU

### Описание реализации

Была реализована гибридная программа, в которой часть массива обрабатывается на CPU с использованием OpenMP, а другая часть — на GPU с использованием CUDA. Для передачи данных между CPU и GPU использовались асинхронные функции `cudaMemcpyAsync` и CUDA streams.

---

### Профилирование и оптимизация

В ходе профилирования были выявлены следующие узкие места:
- накладные расходы на передачу данных между CPU и GPU;
- синхронизация потоков и ожидание завершения вычислений на GPU.

В качестве оптимизации была использована асинхронная передача данных и перекрытие вычислений на CPU с выполнением CUDA-ядра, что позволило уменьшить общее время выполнения программы.

---

## Задание 4. Анализ масштабируемости распределенной программы (MPI)

### Описание реализации

Для анализа масштабируемости была реализована распределенная программа для вычисления агрегатной функции (суммы элементов массива) с использованием MPI. Эксперименты проводились при различном числе процессов.

---

### Анализ масштабируемости

- **Strong scaling**: при фиксированном размере задачи увеличение числа процессов приводит к снижению времени выполнения, однако ускорение ограничивается накладными расходами на коммуникации.
- **Weak scaling**: при увеличении размера задачи пропорционально числу процессов масштабируемость выше, однако влияние коммуникаций также остается значительным.

Коммуникационные операции (`MPI_Reduce`, `MPI_Allreduce`) оказывают существенное влияние на производительность и ограничивают масштабируемость алгоритма.

---

## Выводы

1. Параллельные вычисления на CPU с использованием OpenMP позволяют значительно сократить время выполнения, однако ускорение ограничено законом Амдала.
2. Производительность GPU существенно зависит от паттернов доступа к памяти, при этом коалесцированный доступ является критически важным.
3. Гибридные приложения CPU + GPU наиболее эффективны при использовании асинхронных передач данных и правильной балансировке нагрузки.
4. Масштабируемость распределенных программ ограничивается затратами на коммуникацию между процессами.

---

## Контрольные вопросы

### 1. В чём отличие измерения времени выполнения от профилирования?

Измерение времени выполнения дает общее время работы программы, тогда как профилирование позволяет определить распределение времени между отдельными функциями и выявить узкие места.

---

### 2. Какие виды узких мест характерны для CPU, GPU и распределённых программ?

Для CPU характерны ограничения пропускной способности памяти и синхронизации потоков, для GPU — неэффективный доступ к глобальной памяти и низкая загрузка вычислительных блоков, для распределённых программ — задержки коммуникаций между процессами.

---

### 3. Почему увеличение числа потоков или процессов не всегда приводит к ускорению?

Увеличение числа потоков или процессов приводит к росту накладных расходов на синхронизацию и коммуникации, а также ограничивается долей последовательного кода.

---

### 4. Как законы Амдала и Густафсона применяются при анализе масштабируемости?

Закон Амдала описывает ограничение ускорения при фиксированном размере задачи, а закон Густафсона показывает, что при увеличении размера задачи масштабируемость может быть выше.

---

### 5. Какие факторы наиболее критичны для производительности гибридных приложений?

Критичными факторами являются накладные расходы на передачу данных между CPU и GPU, балансировка нагрузки и возможность перекрытия вычислений с передачей данных.

---
