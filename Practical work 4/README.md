## Контрольные вопросы

### 1. Чем отличаются типы памяти в CUDA и в каких случаях их использовать?

В архитектуре CUDA используются несколько типов памяти:
- **Регистры** — самая быстрая память, доступная одному потоку. Используется для локальных переменных.
- **Разделяемая (shared) память** — быстрая память, общая для потоков одного блока. Применяется для временного хранения данных, которые используются несколькими потоками.
- **Глобальная память** — основная память GPU, доступная всем потокам, но с высокой задержкой. Используется для хранения больших массивов данных.
- **Константная и текстурная память** — специализированные типы памяти, оптимизированные для чтения и определенных шаблонов доступа.

Выбор типа памяти определяется объемом данных, частотой обращений и необходимостью совместного доступа потоков.

### 2. Как использование разделяемой памяти влияет на производительность?

Использование разделяемой памяти позволяет существенно повысить производительность CUDA-программ за счет:
- уменьшения количества обращений к глобальной памяти;
- более низкой задержки доступа по сравнению с глобальной памятью;
- возможности быстрого обмена данными между потоками одного блока.

Наибольший эффект достигается, когда данные используются повторно несколькими потоками.

### 3. Что такое коалесцированный доступ и как его обеспечить?

Коалесцированный доступ — это шаблон обращения к глобальной памяти, при котором потоки одного варпа обращаются к соседним адресам памяти.  
Для обеспечения коалесцированного доступа необходимо:
- использовать линейное вычисление индексов;
- хранить данные в непрерывных массивах;
- выбирать размер блока потоков, кратный размеру варпа (32).

Коалесцированный доступ снижает количество транзакций памяти и повышает производительность.

### 4. Какие сложности возникают при работе с большим объемом данных на GPU?

При работе с большими объемами данных возникают следующие сложности:
- ограниченный объем глобальной и разделяемой памяти GPU;
- высокая задержка доступа к глобальной памяти;
- затраты времени на копирование данных между CPU и GPU;
- снижение производительности при неэффективных шаблонах доступа к памяти.

Эти факторы требуют оптимизации работы с памятью и структуры данных.

### 5. Почему важно минимизировать доступ к глобальной памяти?

Глобальная память имеет значительно большую задержку по сравнению с регистрами и разделяемой памятью. Частые обращения к ней могут стать узким местом программы.  
Минимизация доступа к глобальной памяти позволяет:
- уменьшить задержки выполнения;
- повысить пропускную способность;
- улучшить масштабируемость CUDA-программы.

### 6. Как использовать профилирование для анализа производительности CUDA-программ?

Профилирование позволяет выявить узкие места CUDA-программы.  
Для анализа производительности используются инструменты NVIDIA, такие как:
- **Nsight Systems** — для анализа временной диаграммы выполнения;
- **Nsight Compute** — для анализа использования памяти, варпов и вычислительных ресурсов.

Профилирование помогает определить неэффективные обращения к памяти, низкую загрузку GPU и неоптимальные параметры конфигурации потоков.
