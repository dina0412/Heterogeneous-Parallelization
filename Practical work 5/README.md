## Контрольные вопросы

### 1. В чём отличие стека и очереди?

Стек и очередь отличаются порядком обработки элементов.  
**Стек (LIFO)** работает по принципу «последним пришел — первым вышел»: добавление и удаление элементов происходит с одного конца.  
**Очередь (FIFO)** работает по принципу «первым пришел — первым вышел»: добавление выполняется в конец очереди, а удаление — из начала.

### 2. Какие проблемы возникают при параллельном доступе к данным?

При параллельном доступе нескольких потоков к одним и тем же данным возникают:
- состояния гонки (race conditions);
- потеря или повреждение данных;
- некорректный порядок выполнения операций;
- сложности синхронизации потоков.

Без специальных механизмов защиты параллельные структуры данных работают некорректно.

### 3. Как атомарные операции помогают избежать конфликтов в параллельных структурах данных?

Атомарные операции гарантируют, что операция чтения и записи выполняется как неделимое действие.  
Это позволяет:
- безопасно изменять общие счетчики и индексы;
- избежать одновременной записи несколькими потоками;
- обеспечить корректный порядок операций без использования блокировок.

В реализованных структурах данных атомарные операции используются для управления индексами стека и очереди.

### 4. Какие типы памяти CUDA используются для хранения данных?

В CUDA используются следующие основные типы памяти:
- **Глобальная память** — основная память GPU, доступная всем потокам;
- **Разделяемая (shared) память** — быстрая память, общая для потоков одного блока;
- **Локальная память** — используется для локальных переменных потоков;
- **Регистры** — самая быстрая память, доступная отдельному потоку.

Выбор типа памяти влияет на производительность программы.

### 5. Как синхронизация потоков влияет на производительность?

Синхронизация потоков необходима для корректной работы параллельных программ, однако она увеличивает накладные расходы.  
Частое использование синхронизации может снижать производительность, так как потоки вынуждены ожидать друг друга.  
Поэтому синхронизацию следует использовать только в необходимых местах.

### 6. Почему разделяемая память важна для оптимизации работы параллельных структур данных?

Разделяемая память имеет значительно меньшую задержку доступа по сравнению с глобальной памятью.  
Ее использование позволяет:
- уменьшить количество обращений к глобальной памяти;
- ускорить обмен данными между потоками одного блока;
- повысить общую производительность параллельных структур данных.

Разделяемая память особенно эффективна при совместной обработке данных несколькими потоками.
